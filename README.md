# TCP/UDP 网络调优面板

给跨境服务器用的 Linux 网络参数调优面板。一条命令装好，全中文菜单，改动可一键全部还原。

纯 bash 单文件、无第三方依赖，支持 Debian / Ubuntu / RHEL 系 / openSUSE / Arch / Alpine。

## 快速开始

用 root 执行：

```bash
bash <(curl -sL https://tcp.itssx.com/tcpo)
```

第一次运行会把自己装到 `/usr/local/bin/tcpo`，之后在任意目录敲 `tcpo` 就能打开面板。

也可以走 GitHub，内容一样：

```bash
bash <(curl -sL https://raw.githubusercontent.com/SunSeekerX/tcpo/main/tcpo)
```

介绍网页在 <https://tcp.itssx.com>。

## 它解决什么问题

Linux 默认的网络参数是按局域网设的，跑跨境线路（延迟高、带宽大）会遇到两件事：

- **缓冲区太小**。默认一条连接最多缓存 212KB，而 1Gbps + 200ms 延迟的线路要约 25MB 才能跑满。差两个数量级，带宽再大也用不上。
- **默认算法一遇丢包就砍速**。跨境线路晚高峰有几个百分点的随机丢包很常见，默认的 Cubic 每次丢包都把发送速度减半，于是速度一直上不去。

面板做的就是：按你的实际带宽和延迟把缓冲区算好，并换成 BBR（BBR 直接测量线路真实容量，不被随机丢包误导）。

下面是在容器里用 netem 造模拟链路、在同一条链路上前后对比的实测结果：

| 线路条件 | 调优前 | 调优后 |
|---|---|---|
| 延迟 160ms + 1.5% 丢包，换 BBR | 1.2-1.6 Mbps | 113-121 Mbps |
| 延迟 200ms 无丢包，缓冲区 256KB → 64MB | 14-16 Mbps | 110-124 Mbps |
| 延迟 180ms + 1% 丢包，跑完菜单 4+5 | 1.1-3.3 Mbps | 105-112 Mbps |
| 延迟 200ms，空闲 8 秒后恢复发送 | 189-190 Mbps | 309-324 Mbps |

你自己机器上的数字会不一样，但方向一致。**线路本身干净时提升有限**：同样 160ms 延迟但不加丢包时，Cubic 141 Mbps、BBR 237 Mbps，只差不到七成。BBR 的价值是抗丢包，不是无条件更快。

## 菜单怎么用

不想一项项点就直接选 **1**。它会问角色、带宽档位（100M/1G 等，也可手输），再跑完基础调优，并尝试限速器扫描 + HTB 整形。公共 iperf3 节点不可用时只跳过整形，基础调优仍然生效。

| 菜单 | 做什么 |
|---|---|
| **1** | **一键全部**：角色 + 带宽 + IPv4/BBR/内核/网卡 + 限速扫描/整形 |
| 2 | IPv4 优先解析，避免 IPv6 绕路导致的连接慢 |
| 3 | 关闭 IPv6（协议族整个关掉，比 2 彻底；再按一次变成恢复） |
| 4 | 换成 BBR + FQ 队列 |
| 5 | 内核参数 · 普通档：缓冲区、队列容量、连接回收 |
| 6 | 内核参数 · 中转档：普通档 + 开启 IP 转发 + MSS Clamp |
| 7 | 网卡队列（RPS / RFS / XPS），让多核一起处理网络中断 |
| 8 | 让队列算法立刻生效（不改也行，重启后自动接管） |
| **20** | **瓶颈诊断**：告诉你调参数到底有没有用、卡在哪 |
| **21** | **效果测量**：对比一段时间内的真实计数变化 |
| **22** | **MTU 探测**：查线路上有没有 MTU 黑洞 |
| **23** | **限速器拐点扫描**：近端 iperf3 实测，找到 policer 后再整形 |
| **24** | **出向整形 开/关**：HTB 聚合限速 + fq 叶子 pacing |
| 30 | 回退全部优化（含整形），还原成第一次运行前的样子 |
| 31 | 在线更新脚本 |
| 32 | 卸载面板（同时回退并清干净） |

**20 / 21 / 22 是只读的**：不改配置、不重启服务、不替你装包（菜单 21 主动压测需要 `iperf3` 时会先问）。**23 会跑真实上行流量**（数 GB / 数分钟，视带宽而定），装 `iperf3` 前也会问。

1-8、23、24 会改机器配置，菜单 30 可完整还原。菜单 **1 不含关闭 IPv6**——要关请自己按 3。

### 5 和 6 选哪个

- 普通 Web、面板、数据库、一般应用服务器 → **5**
- 代理、VPN、WireGuard、隧道、中转节点 → **6**

差别是 6 会额外开 IP 转发和 MSS Clamp，这两项只对「经过本机转发」的流量有用。普通业务机开了 IP 转发相当于把自己变成路由器，防火墙没配好可能被当成开放中继，所以分开。

### 23 / 24 整形怎么工作

家宽/部分商家在端口上有 **policer（突发一超就丢）**。BBR 不限速时平均没超也可能被打穿，重传爆炸、有效吞吐反而低。

菜单 23：

1. 不限速先跑一档：丢包低 → 无限速器，不加整形  
2. 丢包高 → 从实测吞吐往上扫，找「丢包跳变」的拐点  
3. 拐点减去安全余量，用 **HTB 聚合上限 + fq 逐包 pacing** 贴着真实上限跑  

对端越近越准（测的是你的口，不是回国线路）。回车可自动从内置公共 iperf3 节点里选最近可用的；也可填自建 `iperf3 -s` 地址。瓶颈在国际链路而不是端口时，扫描会报「未见限速器」，基础调优仍有效。


### 2 和 3 选哪个

菜单 2 改的是解析优先级（`gai.conf`），让程序在拿到 IPv4 和 IPv6 两个地址时优先用 IPv4。它足够温和，但**只对走系统解析器（`getaddrinfo`）的程序有效** —— Node、Go 这类自带 DNS 解析的运行时不认它。

菜单 3 直接把 IPv6 协议族关掉（`net.ipv6.conf.{all,default,lo}.disable_ipv6=1`），对所有程序一致生效。典型场景是某个上游按 IPv6 出口做拦截，而你的请求恰好由一个不认 `gai.conf` 的程序发出。

先试 2，不管用再上 3。3 关得彻底，代价也更大：

- 接口上的 IPv6 地址会被撤掉，只监听 `::` 的服务可能启动失败
- 连 `lo` 的 `::1` 一起关，绑 `::1` 的本地服务（Redis、PostgreSQL 的常见默认配置）会连不上。执行前面板会列出当前在监听 IPv6 的进程名给你过目
- **这台机器只有 IPv6 入口时，关掉就等于自断 SSH**。面板会在执行前检查：当前 SSH 会话是不是 IPv6 连进来的、有没有 IPv4 默认路由、出口网卡上有没有 IPv4 地址。任一命中就直接拒绝、不给确认选项。信息不全时同样拒绝（缺 `ip` 命令、`SSH_CONNECTION` 被 screen/tmux 丢掉且又证明不了有 IPv4 通路）——探测不了就不做，不 fail-open

按一次是关，关掉之后同一个键变成「恢复 IPv6」，按第二次就写回原值 —— 不用为了开回 IPv6 去跑菜单 30（那会把 BBR、缓冲区等全部优化一起回退）。

菜单 **1 一键全部优化不含这一项**：关掉一整个协议族对大多数机器是意外的语义变更，要关就自己按 3。

### 诊断（菜单 20）能看什么

参数写进去了不代表有效果。内核自己记着每条连接卡在哪，菜单 20 把它读出来翻译成结论：

- **发送缓冲不够** → 加大缓冲区有用，菜单 5 正好治这个
- **对端窗口不够** → 你这边调没用，得对端也调
- **应用喂不满** → 瓶颈在程序本身（并发不够、单线程、上游慢），调内核参数不会有变化
- **重传率高** → 线路在丢包，BBR 能缓解但治不好，考虑换线路
- **缓冲区开太大** → 内核在强制收缩缓冲，这时该往下调而不是继续加

诊断需要有流量才有判断力，请在业务跑着或压测时执行。

## 常见问题

### 会不会把机器搞坏

面板只做两件事：往 `/etc` 下写配置文件、改运行时的内核参数。不换内核、不编译模块、不装隧道，最坏情况是「参数没生效」，不会出现「重启开不了机」。

第一次运行前会把所有要改的参数原值存一份快照，菜单 30 按快照逐个写回，不是硬编码猜一个默认值。

### 先看看会改什么

```bash
TCPO_DRYRUN=1 tcpo
```

演练模式把所有写入重定向到临时目录，一个字节都不进 `/etc`，退出时把「本来会写入的文件」连内容一起打印出来。这个模式不需要 root，可以先在自己电脑上看清楚再决定。

### 重启之后还在吗

先说清一件事：**面板改的东西分三类，开机恢复的机制各不相同**，不能一起看。

| 改的是什么 | 谁负责在开机时恢复 |
|---|---|
| 内核参数（菜单 4/5/6 写的 `/etc/sysctl.d/`） | systemd，或发行版自带的 sysctl 服务 |
| BBR 模块（`tcp_bbr` 不是内建时） | 只有 systemd 会读 `/etc/modules-load.d/` |
| 网卡队列与 qdisc（菜单 7/8 写的 `/sys` 下的东西） | 只有面板自己装的 systemd unit 或它生成的重放脚本 |

面板会分别探测这三项、分别报结论，不会拿一项的结果替另一项背书。

**内核参数**这一项有三种结果：

- **带 systemd 的机器**（绝大多数）：在。开机由 systemd 重新应用 `/etc/sysctl.d/`，面板报「已持久化」。
- **不带 systemd 但发行版自带 sysctl 服务**：也在。sysvinit 的 `procps`、openrc 的 `sysctl` 服务（需要真的 `rc-update add` 过，Alpine 默认没加）同样会应用 `/etc/sysctl.d/`。面板会报「已持久化」，并注明是**系统自带的服务在重放，不是本面板的脚本** —— 这句区分很重要，否则你会以为下面那个重放脚本已经挂好了。
- **都没有**（WSL2 默认、容器、没加 sysctl 服务的 openrc）：重启回原值。面板会说「本次已生效，但重启后回到原值」，并生成重放脚本 `/usr/local/bin/tcp-dashboard-sysctl-apply.sh`，告诉你挂到哪里（WSL 是 `wsl.conf` 的 `[boot] command`，sysvinit 是 `rc.local` 之类）。容器则直接告诉你持久化要在宿主上做。

**BBR** 单独看一眼：`sysctl` 会重放不等于 BBR 会回来。`tcp_bbr` 是内核模块时得有人在开机 `modprobe`，而 `/etc/modules-load.d/` 只有 systemd 会读；模块没加载时内核会直接拒绝 `bbr`，于是重启后静默回到 cubic 而 sysctl 那边看着全绿。有 systemd 的机器面板会自动把 `modules-load.d` 配齐；没有的机器由那个重放脚本负责（它内部先 `modprobe` 再应用参数）。

**网卡队列和 qdisc**（菜单 7、8）跟上面两项完全无关，这点最容易搞错：它们写的是 `/sys` 下的运行时设置，不是 sysctl，`procps` / openrc 的 sysctl 服务**不会**重放它们。所以：

- 有 systemd → 面板装一个 `tcp-dashboard-nic.service`，开机执行 `tcp-dashboard-nic-apply.sh` 重放
- 没有 systemd → 面板生成 `tcp-dashboard-nic-apply.sh` 让你自己挂，同时也生成 `tcp-dashboard-sysctl-apply.sh` 并建议**只挂后者**（它内部会调前者，还会顺手重放菜单 7 写的 RFS 全局流表 —— 那一项是 sysctl，不在网卡 plan 里，只挂 nic-apply 会让 RFS 半失效）。**这台机器本来会不会重放 `/etc/sysctl.d/` 都一样**，队列设置总得有人管

**面板不会自动改你的开机方式**，挂不挂那些脚本由你决定 —— 那超出「网络参数」的范围，也不再是文件级可完整回退的改动。

你按提示挂好之后再进面板，它会认出重放脚本在本次开机早期跑过，改口说「开机重放脚本有运行痕迹」。注意措辞是「痕迹」而不是「已持久化」：运行痕迹只能证明它跑过，证明不了那行挂载配置现在还在（你可能跑过一次之后又把它删了）。想真正确认，最直接的办法是**重启后回面板看状态**，显示 `[保守档]` / `[中转档]` 就是真的重放了。

### 会自动更新吗

不会。启动时只读一个版本号文件，有新版就在标题栏提示一行，换不换由你敲菜单 31 决定 —— 这台机器可能正在跑业务，不该让远端代码在你没同意时改它。

- 不想让它联网检查：`TCP_DASHBOARD_NO_CHECK=1 tcpo`
- 检查有 3 秒超时、24 小时缓存，失败完全静默，不影响面板启动
- 菜单 31 更新前会校验拉到的内容真的是这个脚本（首行是 `#!/bin/bash`、语法能过、含本项目特征串），任一条不满足就放弃并保留当前版本

### 目标机不能上外网怎么装

脚本是单文件，离线安装就是「把一个文件传上去」。在能上网的机器上下载，再传过去：

```bash
curl -fL -o tcpo https://tcp.itssx.com/tcpo
scp tcpo root@1.2.3.4:/root/
ssh root@1.2.3.4 'bash /root/tcpo'
```

本地文件执行时脚本不联网，所以这条路完全不需要目标机有外网。

没有 `scp`（只有网页版控制台）时走剪贴板，在目标机上敲：

```bash
cat > /root/tcpo <<'TCPSH_EOF'
# 这里粘贴 tcpo 全文，然后按 Ctrl-D
TCPSH_EOF
bash /root/tcpo
```

`<<'TCPSH_EOF'` 的单引号必须加，不加的话 shell 会展开脚本里的 `$` 和反引号，内容被改坏还不报错。粘完可以用 `wc -c /root/tcpo` 核对一下大小。

### 需要先装什么工具吗

不需要，脚本本身零依赖。但部分功能要借助系统工具，最小化安装的系统常常没有：

- 写入类菜单（1-8）用到 `ping`（测延迟算缓冲区）、`ss`（保留监听端口）、`ethtool`（读网卡队列数）、`iptables`（中转档的 MSS Clamp）、`sysctl`（读原值、应用、校验）。缺了会自动装，支持 `apt-get` / `dnf` / `yum` / `zypper` / `pacman` / `apk` 六种包管理器；装不上就降级并告诉你影响和手动补装命令
- `sysctl` 是唯一一个「装不上就不改任何东西」的：读不到原值就没有可靠的回退依据，硬跑会让回退静默跳过一切（RHEL 系最小化镜像实测不自带它，包名 `procps-ng`）
- 只读菜单（20、21、22）还会用到 `nstat`（读计数器）、`tc`（看队列）、`tracepath`（探路径）。这三项加上前面几个，只读菜单一律**不会自动装**，缺哪个就跳过对应指标并打印补装命令；唯一需要你点头的是 `iperf3`（菜单 21 的主动压测会产生真实流量）

装包套了 180 秒超时，有进度显示，完整输出留在 `/var/lib/tcp-dashboard/pkg.log`。软件源不通时不会卡死，会明确告诉你哪个包装失败。

### 底部状态栏那行是什么意思

- 菜单项状态各有三态：`[已开启]`（菜单 3 是 `[已关闭]`）是配置在且当前真的在跑；`[配置未生效]` 是配置文件写着但运行值不符；`[未开启]` / `[未关闭]` 是压根没配过。看到 `[配置未生效]` 通常是两种情况：被系统里别的配置文件盖掉了，或者这台机器开机没人重放配置（见上面「重启之后还在吗」）
- BBR 后面的版本标签：`[BBRv3]` 是确认在跑 BBRv3；`[模块未报版本]` 是模块没有报版本号（主线内核的 BBR 就不报，所以这不代表版本旧，只是查不出来）；`[版本未知]` 是查版本的通路本身不可用

### 缓冲区那个数字是怎么算的

按「带宽 × 延迟」（BDP）算，不是拍内存百分比：

```
BDP = 带宽Mbps × 125 × 延迟ms
缓冲上限 = min(BDP × 2.5, 总内存 5%, TCP 全局池 ÷ 16)，再限制在 8MB - 256MB
```

延迟由脚本 ping 几个公共地址实测（探不到就按跨境典型值 150ms），带宽会问你，并把网卡的链路速率报出来做参考（不拿它当默认值 —— 物理口千兆不等于真能跑千兆）。

推导过程会原样写进配置文件开头，三个月后想起来「为什么是 11MB」还能查到：

```
#   带宽        1000 Mbps（网卡链路速率 10000 Mbps）
#   RTT         36 ms (实测 1.1.1.1 8.8.8.8 9.9.9.9 取最小)
#   BDP         1000 x 125 x 36 = 4 MB
#   x2.5 余量   10 MB   （留给丢包重传期间的在途数据）
#   内存 5%     1604 MB   （本机内存 32094 MB）
#   TCP 全局池  2997 MB ÷ 16 = 187 MB   （tcp_mem 上限，所有连接共用）
#   最终取值    11 MB  <- BDP x2.5
```

### 会改哪些文件

配置文件（都在 `/etc` 下）：

| 路径 | 内容 | 回退时 |
|---|---|---|
| `/etc/sysctl.d/10-bbr.conf` | BBR + fq | 删除 |
| `/etc/sysctl.d/zz-network-performance.conf` | 内核参数主配置 | 删除 |
| `/etc/sysctl.d/zz-network-rfs.conf` | RFS 流表（菜单 7） | 删除 |
| `/etc/sysctl.d/zz-disable-ipv6.conf` | 关闭 IPv6（菜单 3） | 删除，并把三个 `disable_ipv6` 写回原值 |
| `/etc/security/limits.d/99-network-performance.conf` | 登录 shell 的文件句柄上限 | 删除 |
| `/etc/systemd/system.conf.d/zz-tcpo-limits.conf` | systemd 服务的句柄上限 | 删除 |
| `/etc/modules-load.d/bbr.conf` | 开机加载 BBR 模块 | 删除 |
| `/etc/gai.conf` | IPv4 优先（原文件备份成 `gai.conf.bak`） | 还原备份 |
| iptables 的 MSS Clamp 规则（只有中转档会加） | 带 `tcpo-mss-clamp` 标记 | 按标记删除，不动你自己加的规则 |

开机重放相关（按机器情况生成，不一定全都有）：

| 路径 | 什么时候生成 | 回退时 |
|---|---|---|
| `/etc/systemd/system/tcp-dashboard-nic.service` | 有 systemd，且跑过菜单 7 或 8 | 关闭并删除 |
| `/usr/local/bin/tcp-dashboard-nic-apply.sh` | 跑过菜单 7 或 8 就生成，**有没有 systemd 都会**：有 systemd 时它是上面那个 unit 开机执行的目标，没有时留给你自己挂 | 删除 |
| `/etc/networkd-dispatcher/routable.d/50-tcp-dashboard` | 机器装了 systemd-networkd（补「网卡重连后设置回默认」的缺口） | 删除 |
| `/usr/local/bin/tcp-dashboard-sysctl-apply.sh` | 两种情况：① 菜单 4/5/6 发现这台机器开机不会重放 `/etc/sysctl.d/`；② 跑过菜单 7 而这台机器没有 systemd（此时**即使它会重放 sysctl 也照样生成** —— 队列设置和 RFS 全局表得靠它） | 删除；你挂在 `wsl.conf` / `rc.local` 里的那行要自己清 |

容器里不生成 `tcp-dashboard-sysctl-apply.sh`（持久化由宿主决定，生成了也没用），面板会直接这么告诉你；`tcp-dashboard-nic-apply.sh` 仍会写出来。

状态文件（都在 `/var/lib/tcp-dashboard/`）：

| 文件 | 内容 | 回退时 |
|---|---|---|
| `original-values` | 第一次运行前的参数原值快照，回退就靠它 | 卸载时才删 |
| `taken-over` + `takeover-<时间戳>/` | 被接管的冲突文件清单与整份备份 | 逐条还原 |
| `nic.plan` | 网卡队列设置清单，开机重放脚本读它 | 删除 |
| `qdisc.plan` | 菜单 8 的 qdisc 重放清单 | 删除，并把队列交回内核按默认重建 |
| `apply.log` / `pkg.log` / `version-check` / `sysctl-apply.stamp` | 应用日志、装包日志、版本检查缓存、重放脚本的运行痕迹 | 卸载时才删 |

如果系统里已有别的配置文件写了同一个参数，面板会把冲突的那几行注释掉并整份备份，只动冲突行，不禁用整个文件。回退时从最早那份备份还原。

### 有些参数为什么不设

配置文件末尾有一段注释，列了「社区脚本普遍在写、但本脚本故意不写」的参数和原因。几条常见的：

- `tcp_mem` / `udp_mem` 单位是页不是字节，同类脚本大面积搞错，内核自己会按内存分档，保持默认更好
- `tcp_tw_recycle` 在 4.12 内核就删掉了，写了会报错
- `tcp_fack` / `tcp_low_latency` 内核文档明写「已无任何效果」
- 把 `tcp_sack` / `tcp_timestamps` / `tcp_window_scaling` 设 0 对跨境线路是灾难，关掉窗口缩放等于把窗口锁在 64KB

写下原因是为了防止以后的版本把有意的省略当成遗漏补回去。

在容器里跑写入类菜单时，`net.core.*` 这类参数多数写不进去（不在容器的命名空间内），面板会区分「容器限制」和「本内核不支持」分别提示，不假报成功。

## 不做什么

- **不换内核**（XanMod BBRv3 / BBRplus / 锐速那类）。最坏情况是重启开不了机，而这个面板是通过 SSH 用的，出事就失联，跟「可完整回退」冲突
- **不编译内核模块**，**不集成隧道 / FEC**
- **不做全能面板**：SSH 加固、防火墙、swap、DNS、流媒体解锁、跑分一律不加
- **不自动改开机方式**，也**不自动更新自己**

## 仓库结构

```
tcpo                 全部实现，单文件纯 bash，无第三方依赖
VERSION                版本号，与 tcpo 的 SCRIPT_VERSION 必须一致
index.html             介绍网页，单页，CSS 内联，中英双语文案都在里面
Jenkinsfile            把网页与 tcpo 同批发到 nginx 静态目录
test/
  site-test.sh         站点与发布配置（不联网、零副作用，几秒）
  distro-test.sh       六大发行版系容器兼容性测试
  effect-test.sh       netem 造长肥链路，实测参数的真实效果
```

上线的只有 `index.html`、`tcpo`、`VERSION` 三个文件，由 `Jenkinsfile` 的白名单控制。
